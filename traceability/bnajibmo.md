## Generators

- Paths come from a pool of five names, each in three spellings (`a.ts`, `./a.ts`, `/project/a.ts`), so the same file gets read more than once under different names. The gate has to count it once.
- Each read succeeds, fails (missing file), or hits a directory. Failed reads and directories must not appear in the list.
- A request makes 1 to 4 edit/write/apply_patch calls; R7 runs 1 to 4 such requests.
- The user's answer is drawn from Continue, Cancel, and dismiss (closing the prompt without choosing). R8 draws a typed question and an answer from short lowercase strings.

## Step 3 triage

- First run: R1, R3, R4, R5, R6, R7, and R8 passed.
- R2 failed on the shrunk counterexample `[[], "a", "Continue"]`: with no files read, a bash call ran with no prompt. Code bug. The gate only held edit, write, and apply_patch. Fix: added bash to the held tools in both gates (`packages/core/src/session/runner/walkthrough.ts` and `packages/opencode/src/session/walkthrough.ts`) and updated the model instructions in `packages/core/src/plugin/agent.ts` to name bash.
- After the fix all 8 properties pass, and the existing walkthrough tests in both packages (`packages/core/test/session-walkthrough.test.ts`, `packages/core/test/session-runner.test.ts`, `packages/opencode/test/session/prompt.test.ts`) still pass.
